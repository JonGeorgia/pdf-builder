about_text=PDFuse is a program for creating PDF documents from Markdown-formatted text files.\nPDFuse produces PDF documents that are equally convenient for humans and for use by AI models in RAG systems (Retrieval-Augmented Generation).\n👤\nFor a human — it is a beautifully typeset document: with a title page, fonts, logos, tables, images.\n🤖\nFor AI — it is a machine-readable data source. All source files are embedded into the resulting PDF: Markdown texts, CSS style, images, etc. And this embedded source Markdown (the most convenient format for chunking and indexing while preserving document structure (headings, lists, tables)) can be extracted and used.\n\nThe program has two main modes:\n✔ Markdown → PDF    - Building PDF from ready-made Markdown files\n✔ PDF → Markdown    - Restoring sources from PDF.\n   There is also an option to produce a PDF without a text layer and without attachments (a graphic monolith).\n\nMODE «Markdown → PDF»\nRequired data structure for PDF generation:\nMy project/\n    ├──File 1.md\n    ├──File 2.md\n    ├──style/\n    │  ├──style.css\n    │  ├──logo.png\n    │  └──fonts/\n    │        └──MyFont-Bold.ttf\n    └──images/\n       ├──Picture 1.jpg\n       └──Picture 2.png\n❗ The data folder must contain a subfolder style/ with the file style.css, which describes the PDF layout (fonts, colors, margins, page layout, etc.).\n✔ Optionally, the style/ folder may also contain logos, title-page images and other resources (they are referenced from style.css);\n✔ If the PDF document must contain images, they need to be placed in the subfolder images/.\n\nTo start generating a PDF, select the folder containing the required data and press the "Generate PDF" button. The program scans the folder containing one or more .md files (source texts of the documents) and, for each .md file, creates a PDF file with the same name in the same folder.\nAll .md files in the folder are converted at once, and the same style described in style.css is applied to each of them.\n\nCSS SUPPORT\nThe layout of the PDF documents is described in the style.css file and applied via the WeasyPrint engine. Selectors, fonts, colors, gradients, pseudo-elements, multi-page layout, @page rules, page counters, headers and footers and other print-oriented CSS features are supported. The same .CSS can be used for an entire series of documents to ensure a consistent visual style.\n\nIMAGES\nAll images that should appear in the generated PDFs must be placed in the subfolder images/. The subfolder holds images for all .md files if there are several.\nReferences to images in the .md files must be inserted as: ![Picture 1](images/001_voice_setup.jpg).\n\nMODE «PDF → Markdown»\nIn this mode, the program extracts the source data from which the selected PDF file was created.\n✔ If the PDF was created by PDFuse and contains the embedded source file, the program restores the full structure: the source .md file, the style folder style/ and the images folder images/.\n✔ If the PDF was created by another program, only the text layer is extracted. Images and text embedded in pictures are not recognised (no OCR is performed).\n\nUSE IN RAG SYSTEMS\nWhen generating a PDF, the program embeds the source files into it: Markdown texts, CSS style and images. They are packed into a single block and stored in the PDF structure as an attachment named SOURCES.bin.\nThanks to this:\n✔ Information in the PDF remains machine-readable (not an image requiring OCR) and is easily extracted in RAG systems;\n✔ At any time, the source Markdown can be retrieved — the most convenient format for chunking, since the document structure (headings, lists, tables, etc.) is preserved exactly as intended by the author;\n✔ The document remains "alive": humans read the PDF while the AI model works with the sources — with no loss of quality on either side.\n\nHOW TO EXTRACT THE SOURCES\nThere are two ways:\n✔ Open PDFuse in the «PDF → Markdown» mode.\nThe program will unpack SOURCES.bin itself and restore the entire folder structure next to the PDF.\n✔ Extract the attachment directly, without PDFuse.\nSOURCES.bin is an ordinary PDF attachment, accessible with any PDF tool.\nFor example:\n • in Adobe Acrobat — the "Attachments" panel;\n • in PDF-XChange Viewer — Attachments → SOURCES.bin → Save;\n • with the command mutool extract file.pdf (MuPDF tools).\n\nThe resulting SOURCES.bin is a compressed archive (zlib + ZIP), where the first 17 bytes are an archive marker and the rest is compressed data.\nFor manual unpacking: zlib-flate -uncompress < SOURCES.bin > sources.zip, then unzip sources.zip. Inside you will find the same structure as in the original folder: .md files, style/style.css and images/.\n\nA RAG system can work with these sources directly — for example, splitting Markdown into semantic chunks while preserving the heading structure, which yields precise chunking and high-quality answers.\n\nMore examples of extracting source data from the attachment and using it in RAG systems can be found on the project page on GitHub.\n\nLANGUAGE SUPPORT\nRussian, English, German, French.\n\n\nPS: PDFuse is completely free for any use, but includes the following libraries:\n❗ pandoc (https://github.com/jgm/pandoc), distributed under GNU GPL v2+, and\n❗ WeasyPrint (https://github.com/Kozea/WeasyPrint), distributed under BSD-3-Clause.\n The source code of these libraries is available at the links above.\n\nWe will be glad if our program helps you organise your documentation, create wonderful textbooks or any other document :)\n\n                                                                                                        AutomatonLab
