about_text=PDFuse — программа для создания PDF-документов из текстовых документов с разметкой Markdown.\nPDFuse создаёт PDF документы одинаково удобные и для человека, и для использования ИИ моделями в RAG-системах (Retrieval-Augmented Generation).\n👤\nДля человека — это красиво свёрстанный документ: с титульной страницей, шрифтами, логотипами, таблицами, изображениями.\n🤖\nДля ИИ — это машиночитаемый источник данных. В готовый PDF вкладываются все исходные файлы: Markdown-тексты, CSS-стиль и изображения и т.д.. И этот вложенный исходный Markdown (самый удобный формат для разбиения на чанки и индексации с сохранением структуры документа (заголовки, списки, таблицы)) можно извлечь и использовать.\n\nПрограмма работает в двух основных режимах:\n✔ Markdown → PDF    - Сборка PDF из готовых Markdown-файлов\n✔ PDF → Markdown   - Восстановление исходников из PDF.\n   Плюс есть возможность сформировать PDF без текстового слоя и вложений (графический монолит).\n\nРЕЖИМ «Markdown → PDF»\nТребуемая для генерации PDF структура данных:\nМой проект/\n    ├──Файл 1.md\n    ├──Файл 2.md\n    ├──style/\n    │  ├──style.css\n    │  ├──logo.png\n    │  └──fonts/\n    │        └──MyFont-Bold.ttf\n    └──images/\n       ├──Рисунок 1.jpg\n       └──Рисунок 2.png\n❗ В папке с данными обязательно должна быть подпапка style/ с файлом style.css в котором описано оформление PDF (шрифты, цвета, отступы, разметку страницы и т.д.).\n✔ Дополнительно в style/ можно размещать логотипы, изображения для титульной страницы и другие ресурсы (они подключаются из style.css);\n✔ Если в документе PDF должны быть изображения, то их необходимо поместить в подпапку images/.\n\nДля запуска создания PDF необходимо выбрать папку, в которой лежат требуемые данные и нажать кнопку "Сгенерировать PDF". Программа просканирует файлы в папке, в которой лежат один или несколько файлов .md (исходные тексты документов), и для каждого .md файла в той же папке создаст одноимённый pdf файл.\nВсе .md-файлы в папке конвертируются одновременно, и к каждому применяется один и тот же стиль описанный в style.css.\n\nПОДДЕРЖКА CSS\nОформление PDF документов описывается в файле style.css и применяется через движок WeasyPrint. Поддерживаются селекторы, шрифты, цвета, градиенты, псевдоэлементы, многостраничная вёрстка, правила @page, счётчики страниц, колонтитулы и другие возможности CSS для печати. Один и тот же .CSS можно использовать для целой серии документов, чтобы обеспечить единый стиль оформление.\n\nИЗОБРАЖЕНИЯ\nВсе изображения, которые должны быть в создаваемых PDF, необходимо поместить в подпапку images/. В подпапку помещаются изображения для всех .md файлов, если их несколько.\nСсылки на изображение в .md файлах необходимо вставлять в виде: ![Рисунок 1](images/001_voice_setup.jpg).\n\nРЕЖИМ «PDF → Markdown»\nВ этом режиме программа позволяет извлечь из выбранного файла PDF исходные данные, из которых файл был создан.\n✔ Если PDF был создан программой PDFuse и в нём есть вложенный файл исходников, то программа восстановит полную структуру: исходный .md-файл, папку со стилями style/ и папку с изображениями images/.\n✔ Если PDF был создан другой программой, то извлекается только текстовый слой. Изображения и текст из картинок программа не распознаёт (OCR не выполняется).\n\nИСПОЛЬЗОВАНИЕ В RAG-СИСТЕМАХ\nПри генерации PDF программа вкладывает в него исходные файлы: Markdown-тексты, CSS-стиль и изображения. Они упакованы в единый блок и хранятся в структуре PDF как вложение с именем SOURCES.bin.\nБлагодаря этому:\n✔ Информация из PDF остаётся машиночитаемой (не картинкой требуемой распознавания OCR) и хорошо извлекается в RAG-системах;\n✔ В любой момент можно достать исходный Markdown — самый удобный формат для разбиения на чанки, поскольку структура документа (заголовки, списки, таблицы и т.д.) сохраняется в том виде, как задумал автор документа;\n✔ Документ остаётся «живым»: человек читает PDF, а ИИ-модель работает с исходниками — без потери качества ни на одной стороне.\n\nКАК ИЗВЛЕЧЬ ИСХОДНИКИ\nЕсть два способа:\n✔ Открыть PDFuse в режиме «PDF → Markdown».\nПрограмма сама распакует SOURCES.bin и восстановит всю структуру папки рядом с PDF.\n✔ Извлечь вложение напрямую, без PDFuse.\nSOURCES.bin — это обычное вложение PDF, доступное любым инструментом для работы с PDF.\nНапример:\n • в Adobe Acrobat — панель «Вложения» (Attachments);\n • в PDF-XChange Viewer — Attachments → SOURCES.bin → Save;\n • командой mutool extract file.pdf (MuPDF tools).\n\nПолученный SOURCES.bin — это сжатый архив (zlib + ZIP), где первые 17 байт это метка архива, а всё остальное сжатые данные.\nДля распаковки вручную: zlib-flate -uncompress < SOURCES.bin > sources.zip, затем unzip sources.zip. Внутри — та же структура, что и в исходной папке: .md-файлы, style/style.css и images/.\n\nRAG-система может работать с этими исходниками напрямую — например, разбивать Markdown на семантические чанки, сохраняя структуру заголовков, что даёт точное разбиение и высокое качество ответов.\n\nПодробнее примеры извлечения исходных данных из вложения и их использование в RAG можно прочитать на странице проекта на GitHub.\n\nПОДДЕРЖКА ЯЗЫКОВ\nРусский, английский, немецкий, французский.\n\n\nПС: Программа PDFuse является полностью бесплатной для любого использования, но включает библиотеки:\n❗ pandoc (https://github.com/jgm/pandoc), распространяемый под GNU GPL v2+, и\n❗ WeasyPrint (https://github.com/Kozea/WeasyPrint), распространяемый под BSD-3-Clause.\n Исходные коды библиотек доступны по указанным ссылкам.\n\nМы будем рады если наша программа позволит вам упорядочить свою документацию, создать замечательные учебники или любой другой документ :)\n\n                                                                                                        AutomatonLab
