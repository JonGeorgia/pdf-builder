about_text=PDFuse est un programme de création de documents PDF à partir de fichiers texte au format Markdown.\nPDFuse produit des documents PDF tout aussi pratiques pour l'être humain que pour l'utilisation par des modèles d'IA dans des systèmes RAG (Retrieval-Augmented Generation).\n👤\nPour l'humain — un document joliment mis en page : avec page de titre, polices, logos, tableaux, images.\n🤖\nPour l'IA — une source de données lisible par machine. Tous les fichiers sources sont intégrés au PDF final : textes Markdown, style CSS, images, etc. Et ce Markdown source intégré (le format le plus pratique pour le découpage en chunks et l'indexation tout en préservant la structure du document (titres, listes, tableaux)) peut être extrait et utilisé.\n\nLe programme fonctionne selon deux modes principaux :\n✔ Markdown → PDF    - Assemblage d'un PDF à partir de fichiers Markdown prêts\n✔ PDF → Markdown    - Restauration des sources à partir d'un PDF.\n   Il existe également la possibilité de produire un PDF sans couche de texte ni pièces jointes (un monolithe graphique).\n\nMODE « Markdown → PDF »\nStructure de données requise pour la génération du PDF :\nMon projet/\n    ├──Fichier 1.md\n    ├──Fichier 2.md\n    ├──style/\n    │  ├──style.css\n    │  ├──logo.png\n    │  └──fonts/\n    │        └──MyFont-Bold.ttf\n    └──images/\n       ├──Image 1.jpg\n       └──Image 2.png\n❗ Le dossier de données doit contenir un sous-dossier style/ avec le fichier style.css, qui décrit la mise en page du PDF (polices, couleurs, marges, mise en page, etc.).\n✔ En option, le dossier style/ peut également contenir des logos, des images pour la page de titre et d'autres ressources (elles sont référencées depuis style.css) ;\n✔ Si le document PDF doit contenir des images, elles doivent être placées dans le sous-dossier images/.\n\nPour lancer la génération du PDF, sélectionnez le dossier contenant les données requises et cliquez sur le bouton « Générer le PDF ». Le programme analyse le dossier contenant un ou plusieurs fichiers .md (textes sources des documents) et, pour chaque fichier .md, crée un fichier PDF du même nom dans le même dossier.\nTous les fichiers .md du dossier sont convertis en une seule fois, et le même style décrit dans style.css est appliqué à chacun d'eux.\n\nPRISE EN CHARGE DE CSS\nLa mise en page des documents PDF est décrite dans le fichier style.css et appliquée via le moteur WeasyPrint. Les sélecteurs, polices, couleurs, dégradés, pseudo-éléments, mises en page multi-pages, règles @page, compteurs de pages, en-têtes et pieds de page ainsi que d'autres fonctionnalités CSS orientées impression sont pris en charge. Le même .CSS peut être utilisé pour toute une série de documents afin de garantir un style visuel cohérent.\n\nIMAGES\nToutes les images devant apparaître dans les PDF générés doivent être placées dans le sous-dossier images/. Le sous-dossier contient les images de tous les fichiers .md s'il y en a plusieurs.\nLes références aux images dans les fichiers .md doivent être insérées sous la forme : ![Image 1](images/001_voice_setup.jpg).\n\nMODE « PDF → Markdown »\nDans ce mode, le programme extrait les données sources à partir desquelles le fichier PDF sélectionné a été créé.\n✔ Si le PDF a été créé par PDFuse et contient le fichier source intégré, le programme restaure la structure complète : le fichier .md source, le dossier de styles style/ et le dossier d'images images/.\n✔ Si le PDF a été créé par un autre programme, seule la couche de texte est extraite. Les images et le texte intégré dans les images ne sont pas reconnus (aucun OCR n'est effectué).\n\nUTILISATION DANS LES SYSTÈMES RAG\nLors de la génération du PDF, le programme y intègre les fichiers sources : textes Markdown, style CSS et images. Ils sont regroupés en un seul bloc et stockés dans la structure PDF sous forme de pièce jointe nommée SOURCES.bin.\nGrâce à cela :\n✔ Les informations du PDF restent lisibles par machine (pas une image nécessitant un OCR) et sont bien extraites dans les systèmes RAG ;\n✔ À tout moment, le Markdown source peut être récupéré — le format le plus pratique pour le découpage en chunks, car la structure du document (titres, listes, tableaux, etc.) est préservée exactement telle que l'auteur l'a conçue ;\n✔ Le document reste « vivant » : l'humain lit le PDF, le modèle d'IA travaille avec les sources — sans perte de qualité d'aucun côté.\n\nCOMMENT EXTRAIRE LES SOURCES\nIl existe deux méthodes :\n✔ Ouvrir PDFuse en mode « PDF → Markdown ».\nLe programme décompressera lui-même SOURCES.bin et restaurera toute la structure du dossier à côté du PDF.\n✔ Extraire la pièce jointe directement, sans PDFuse.\nSOURCES.bin est une pièce jointe PDF ordinaire, accessible avec n'importe quel outil PDF.\nPar exemple :\n • dans Adobe Acrobat — le panneau « Pièces jointes » (Attachments) ;\n • dans PDF-XChange Viewer — Attachments → SOURCES.bin → Save ;\n • avec la commande mutool extract file.pdf (MuPDF tools).\n\nLe fichier SOURCES.bin obtenu est une archive compressée (zlib + ZIP), où les 17 premiers octets sont un marqueur d'archive et le reste des données compressées.\nPour décompresser manuellement : zlib-flate -uncompress < SOURCES.bin > sources.zip, puis unzip sources.zip. À l'intérieur, on retrouve la même structure que dans le dossier d'origine : fichiers .md, style/style.css et images/.\n\nUn système RAG peut travailler directement avec ces sources — par exemple, découper le Markdown en chunks sémantiques en préservant la structure des titres, ce qui permet un découpage précis et des réponses de haute qualité.\n\nD'autres exemples d'extraction des données sources depuis la pièce jointe et de leur utilisation dans des systèmes RAG sont disponibles sur la page du projet sur GitHub.\n\nPRISE EN CHARGE DES LANGUES\nRusse, anglais, allemand, français.\n\n\nPS : PDFuse est entièrement gratuit pour tout usage, mais inclut les bibliothèques suivantes :\n❗ pandoc (https://github.com/jgm/pandoc), distribué sous GNU GPL v2+, et\n❗ WeasyPrint (https://github.com/Kozea/WeasyPrint), distribué sous BSD-3-Clause.\n Le code source de ces bibliothèques est disponible aux liens ci-dessus.\n\nNous serons heureux si notre programme vous aide à organiser votre documentation, à créer de merveilleux manuels ou tout autre document :)\n\n                                                                                                        AutomatonLab
